# 为什么推荐命令行而非图形界面

> [!abstract] 一句话结论
> 命令行真正的价值**不是「快」，是「操作能被写成文字」**：可记录、可复制、可传递、可重复。图形界面操作像手势（一次性、谢幕即消失），命令行像语言（天生可留存）。效率只是副产品。

## 核心论据

### 1. 可留存 vs 一次性

一行 `grep -H "final_loss" exp_*/log.txt | awk '{print $1,$NF}' | sort -k2 -n | head -3` 秒级扫完 20 个实验目录取最优 3 个，且能存、能复用、能发群里、能塞进定时任务；鼠标点 25 分钟做完即没，下周重来。

### 2. 管道 `|` + 小工具哲学

每个工具只做一件事、做到极好，纯文本是通用语 → 任意工具可拼（含作者互不认识的）。图形界面是孤岛，工具间只有「复制粘贴」一条羊肠道，你能干啥全看开发者想到了啥。

### 3. 可复现（最重要的一条）

文字精确、截图含混。交接是一份脚本而非 20 张截图文档；软件升级按钮换位，截图文档直接报废。**确定性 > 省事。**

### 4. 没鼠标可点的场景

实验室/云上服务器无桌面，ssh / rsync / nohup / tmux 是门票。

- 连远程：`ssh 用户名@服务器地址`
- 传数据：`rsync -avP data/ 用户名@服务器地址:/home/xxx/data/`
- 后台跑 + 记日志：`nohup python train.py > log.txt 2>&1 &`（`2>&1` 把报错也写进同一文件）
- 长任务保活：`tmux`

### 5. AI 时代反而更值钱

大模型输出本就是文字，操作命令行一步到位；操作图形界面要先识别像素、估算按钮坐标、再截图核对，慢且脆。命令行是「恰好同时适合人和机器」的接口。

## 图形界面的公道话（别扔鼠标）

> [!note] 该用图形界面的情况
>
> - 看图 / 视频 / 数据图表、调界面排版：鼠标碾压式更好。
> - **可发现性**：菜单把能力摊给你看，能撞见「不知道自己需要」的东西。命令行什么都不告诉你——门槛不是「难」，是「你不知道有那个词」。

## 分界线（分工，不是鄙视链）

| 用图形界面 | 用命令行 |
|---|---|
| 需要眼睛判断的 | 要做第二遍的 |
| 需要探索 / 不知道要啥 | 要交给别人的 |
| 一次性的 | 要自动重复的 / 要留记录的 |

> [!tip] 规矩
> **同一件事手动做第三遍还在手动，就是你的（该写成脚本）。**

## 代价与保命习惯

> [!warning] 命令行不拦你
> 删了通常无回收站。作者误删过几天训练结果。
>
> - 批量删前先 `ls` 同样匹配条件，确认选中了啥，再换 `rm`。
> - 危险命令（删 / 覆盖 / 移动）先在无关目录试一次。
> - 重要东西备份 + 全部 git 管起来。
> - **看不懂的命令绝不回车**（AI 生成的也要先看懂它要干啥）。

## 新手路径

- 别背命令表，场景驱动：被重复活儿烦了再去查，记得最死。
- 高频就十几个：`cd/ls`、`cp/mv/rm`、`grep`、`|`、`ssh`、`tmux`、`git`、写个最简单脚本把几条命令攒一起。
- 前两周一定慢（真实存在）；撑过去收益是**复利**——鼠标熟练线性，命令行熟练可累加。
