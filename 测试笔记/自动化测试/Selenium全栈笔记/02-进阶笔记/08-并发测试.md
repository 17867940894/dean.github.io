# 并发测试

> [!info] 本节目标
> 掌握用 pytest-xdist 实现多进程并发、用 ThreadPoolExecutor 实现多线程并发的两种方案，理解各自的适用场景与坑。

相关笔记：[[03-多浏览器兼容]]、[[09-参数化与数据驱动]]

## 一、为什么需要并发

- 用例数量大（100+）时串行执行太慢
- CI 流水线要求测试在 10 分钟内完成
- 需要验证多用户同时操作系统的并发场景

## 二、两种并发方案对比

| 维度         | 多进程（pytest-xdist）   | 多线程（ThreadPoolExecutor）            |
| ---------- | ------------------- | ---------------------------------- |
| Python GIL | 不受 GIL 限制           | 受 GIL 限制，但 Selenium 大部分时间在等 IO，影响小 |
| driver 隔离  | 每个 worker 独立 driver | 需手动管理 driver                       |
| 用例管理       | pytest 自动分配         | 需自己写调度                             |
| 资源占用       | 高（每个进程一个浏览器）        | 中                                  |
| 推荐场景       | **大批量用例并行**         | 多用户并发场景模拟                          |

## 三、pytest-xdist 多进程并发（推荐）

### 3.1 安装

```bash
pip install pytest-xdist
```

### 3.2 基本用法

```bash
# 自动按 CPU 核数启动 worker
pytest -n auto

# 指定 4 个 worker
pytest -n 4

# 指定每个 worker 分配多少用例（默认按文件）
pytest -n 4 --dist=loadfile   # 按文件分配（同文件用例在同一个 worker）
pytest -n 4 --dist=loadscope  # 按类/模块分配
pytest -n 4 --dist=loadgroup  # 按 xdist_group 标记分配
```

### 3.3 driver 管理（关键）

每个 worker 是独立进程，必须 **每个 worker 独立创建 driver**：

```python
# conftest.py
import pytest
from utils.browser import BrowserFactory
from utils.config_loader import load_config

config = load_config()


@pytest.fixture(scope='session')
def driver():
    """每个 worker session 级别创建一个 driver（复用）"""
    browser_cfg = config['browser']
    d = BrowserFactory.create(
        browser=browser_cfg['name'],
        headless=browser_cfg.get('headless', False)
    )
    yield d
    d.quit()
```

> [!warning] scope 选择
> - `scope='function'`：每个用例新建 driver，最隔离但最慢
> - `scope='session'`：worker 内所有用例复用 driver，最快但用例间会共享状态
> - **推荐 `scope='session'` + 每个用例开始时刷新页面 / 退出登录**

### 3.4 并发数控制

```bash
# 经验值：CPU 核数 × 1~2
# 8 核机器推荐 -n 8 或 -n 12
# 太多 worker 会导致内存/CPU 爆满，反而变慢
```

### 3.5 按组分配用例

```python
import pytest

@pytest.mark.xdist_group('login')
def test_login_1():
    ...

@pytest.mark.xdist_group('login')
def test_login_2():
    ...
# 这两个用例会被分配到同一个 worker，避免登录状态冲突
```

```bash
pytest -n 4 --dist=loadgroup
```

### 3.6 资源竞争处理

并发时多个 worker 同时写日志 / 截图会冲突：

```python
# 方案 1：每个 worker 单独的日志/截图目录
import os
import pytest

@pytest.fixture(scope='session', autouse=True)
def worker_dirs(worker_id):
    """worker_id 是 xdist 提供的，如 gw0, gw1"""
    log_dir = f'logs/{worker_id}'
    screenshot_dir = f'screenshots/{worker_id}'
    os.makedirs(log_dir, exist_ok=True)
    os.makedirs(screenshot_dir, exist_ok=True)
    return {'log': log_dir, 'screenshot': screenshot_dir}
```

### 3.7 完整并发配置示例

```python
# conftest.py
import pytest
import os
from utils.browser import BrowserFactory
from utils.config_loader import load_config
from utils.logger import setup_logger

config = load_config()


@pytest.fixture(scope='session')
def driver(worker_id):
    """每个 worker 一个 driver"""
    # 每个 worker 用不同的端口调试
    d = BrowserFactory.create(
        browser=config['browser']['name'],
        headless=config['browser'].get('headless', False)
    )
    yield d
    d.quit()


@pytest.fixture(scope='session', autouse=True)
def setup_worker_logger(worker_id):
    """每个 worker 独立日志"""
    setup_logger(log_dir=f'logs/{worker_id}', name=f'worker_{worker_id}')


# pytest.ini
"""
[pytest]
addopts = -n auto --dist=loadscope --html=reports/report.html --self-contained-html
markers =
    smoke: 冒烟测试
    regression: 回归测试
testpaths = testcases
"""
```

## 四、多线程并发（ThreadPoolExecutor）

适用于"模拟多用户同时操作"的场景。

### 4.1 基本结构

```python
"""
多用户并发模拟
位置：testcases/test_concurrent.py
"""
import pytest
from concurrent.futures import ThreadPoolExecutor, as_completed
from utils.browser import BrowserFactory
from pages.login_page import LoginPage
from pages.home_page import HomePage


def user_login_task(user):
    """单个用户的登录任务"""
    driver = BrowserFactory.create(browser='chrome', headless=True)
    result = {'user': user['username'], 'success': False, 'error': None}
    try:
        login_page = LoginPage(driver)
        login_page.load().login(user['username'], user['password'])
        home = HomePage(driver)
        result['success'] = home.is_loaded()
    except Exception as e:
        result['error'] = str(e)
    finally:
        driver.quit()
    return result


class TestConcurrent:

    @pytest.mark.parametrize('user_count', [5, 10, 20])
    def test_concurrent_login(self, user_count):
        """模拟多用户同时登录"""
        users = [
            {'username': f'user{i}', 'password': 'Pass@123'}
            for i in range(user_count)
        ]

        results = []
        with ThreadPoolExecutor(max_workers=user_count) as executor:
            futures = [executor.submit(user_login_task, u) for u in users]
            for future in as_completed(futures):
                results.append(future.result())

        # 断言所有用户都登录成功
        success_count = sum(1 for r in results if r['success'])
        print(f'成功登录: {success_count}/{user_count}')
        for r in results:
            if not r['success']:
                print(f'失败: {r["user"]} - {r["error"]}')

        assert success_count == user_count
```

### 4.2 多线程 driver 隔离

> [!danger] 多线程必须 driver 隔离
> WebDriver 实例 **不是线程安全** 的，多线程共享一个 driver 会导致命令错乱。每个线程必须创建独立的 driver。

```python
# 错误：多线程共享 driver
driver = webdriver.Chrome()
def task():
    driver.get(...)  # 多个线程同时操作，命令错乱

# 正确：每个线程独立 driver
def task():
    driver = webdriver.Chrome()
    driver.get(...)
    driver.quit()
```

## 六、并发常见坑

### 6.1 端口冲突

每个 Chrome 启动会分配调试端口，并发时可能冲突。`BrowserFactory` 中已用 `Service` 自动分配，无需手动设端口。

### 6.2 文件写入冲突

多 worker 同时写同一个日志文件会乱。解决：每个 worker 独立目录（见 3.6）。

### 6.3 内存溢出

并发太多浏览器，内存爆满。解决：

```bash
# 限制并发数
pytest -n 4

# 或用 headless 模式省内存
pytest -n 8  # 配合 headless=true
```

### 6.4 用例间状态污染

并发时用例间共享同一 driver 会互相干扰。解决：

- 每个用例开始时 `driver.delete_all_cookies()` 或重新登录
- 用 `xdist_group` 把相关用例分到同一 worker
- 关键用例用 `scope='function'` fixture

## 七、性能对比（参考值）

| 模式 | 100 用例耗时 | CPU 占用 | 内存占用 |
| --- | --- | --- | --- |
| 串行 | ~25 min | 低 | 1× |
| `-n 4` | ~7 min | 中 | 4× |
| `-n 8` | ~4 min | 高 | 8× |
| `-n auto`（8 核） | ~4 min | 高 | 8× |

> [!tip] 推荐配置
> 8 核 16G 机器：`-n 6 --dist=loadscope` + headless 模式，平衡速度与资源。
