## 简介

Playwright 测试很简单，它们

- **执行操作**，并且
- **断言状态**是否符合预期。

在执行操作之前无需等待任何内容：Playwright 会在执行每个操作之前自动等待广泛的[可操作性](https://playwright.cn/python/docs/actionability)检查通过。

在执行检查时也无需处理竞态条件——Playwright 断言的设计方式决定了它们描述的是最终需要满足的预期。

就是这样！这些设计选择让 Playwright 用户彻底告别测试中不稳定的超时和竞态检查。

**您将学到**

- [如何编写第一个测试](https://playwright.cn/python/docs/writing-tests#first-test)
- [如何执行操作](https://playwright.cn/python/docs/writing-tests#actions)
- [如何使用断言](https://playwright.cn/python/docs/writing-tests#assertions)
- [测试如何独立运行](https://playwright.cn/python/docs/writing-tests#test-isolation)
- [如何使用测试钩子](https://playwright.cn/python/docs/writing-tests#using-fixtures)

## 第一个测试

请看以下示例，了解如何编写测试。请注意文件名和每个测试名称是如何遵循 `test_` 前缀约定的。

test_example.py

```python
import re
from playwright.sync_api import Page, expect


def test_has_title(page: Page):
    page.goto("https://playwright.cn/")

    # 期望标题“包含”子字符串。
    expect(page).to_have_title(re.compile("Playwright"))


def test_get_started_link(page: Page):
    page.goto("https://playwright.cn/")

    # 单击开始链接。
    page.get_by_role("link", name="Get started").click()

    # 期望页面有一个名为Installation的标题。
    expect(page.get_by_role("heading", name="Installation")).to_be_visible()

```

## 操作 (Actions)

### 导航

大多数测试都将从导航页面到某个 URL 开始。之后，测试将能够与页面元素进行交互。

```python
page.goto("https://playwright.cn/")
```

Playwright 将在继续之前等待页面达到加载状态。了解有关 [page.goto()](https://playwright.cn/python/docs/api/class-page#page-goto) 选项的更多信息。

### 交互

执行操作从定位元素开始。Playwright 为此使用了 [Locators API](https://playwright.cn/python/docs/locators)。定位器代表了一种在任何时刻查找页面上元素的方法，了解有关可用[不同类型](https://playwright.cn/python/docs/locators)定位器的更多信息。Playwright 会在执行操作之前等待元素变为[可操作的](https://playwright.cn/python/docs/actionability)，因此无需等待其可用。

```python
# Create a locator.
get_started = page.get_by_role("link", name="Get started")

# Click it.
get_started.click()
```

在大多数情况下，它会写在一行中

```python
page.get_by_role("link", name="Get started").click()
```

### 基本操作

以下是最受欢迎的 Playwright 操作列表。请注意，还有更多操作，请务必查看 [Locator API](https://playwright.cn/python/docs/api/class-locator) 部分以了解更多信息。

| 操作                      | 描述                   |
| :------------------------ | :--------------------- |
| locator.check()           | 选中输入复选框         |
| locator.click()           | 点击元素               |
| locator.uncheck()         | 取消选中输入复选框     |
| locator.hover()           | 鼠标悬停在元素上       |
| locator.fill()            | 填写表单字段，输入文本 |
| locator.focus()           | 聚焦元素               |
| locator.press()           | 按下单个键             |
| locator.set_input_files() | 选择要上传的文件       |
| locator.select_option()   | 在下拉列表中选择选项   |

## 断言

Playwright 包含一些会一直等待直到满足预期条件的[断言](https://playwright.cn/python/docs/test-assertions)。使用这些断言可以使测试更加稳定且具有弹性。例如，这段代码将一直等到页面获取到包含 "Playwright" 的标题

```python
import re

from playwright.sync_api import expect

expect(page).to_have_title(re.compile("Playwright"))
```

以下是最受欢迎的异步断言列表。请注意，还有[更多](https://playwright.cn/python/docs/test-assertions)内容可供熟悉

| 断言                                | 描述                 |
| :---------------------------------- | :------------------- |
| expect(locator).to_be_checked()     | 复选框已选中         |
| expect(locator).to_be_enabled()     | 控件已启用           |
| expect(locator).to_be_visible()     | 元素可见             |
| expect(locator).to_contain_text()   | 元素包含文本         |
| expect(locator).to_have_attribute() | 元素具有属性         |
| expect(locator).to_have_count()     | 元素列表具有给定长度 |
| expect(locator).to_have_text()      | 元素匹配文本         |
| expect(locator).to_have_value()     | 输入元素具有值       |
| expect(page).to_have_title()        | 页面具有标题         |
| expect(page).to_have_url()          | 页面具有 URL         |

### 测试隔离

Playwright Pytest 插件基于测试夹具（fixtures）的概念，例如传入测试中的[内置 page 夹具](https://playwright.cn/python/docs/test-runners)。[由于浏览器上下文（Browser Context），页面在测试之间是隔离的](https://playwright.cn/python/docs/browser-contexts)，这相当于一个全新的浏览器配置文件，其中每个测试都能获得一个全新的环境，即使多个测试在同一个浏览器中运行也是如此。

`test_example.py`

```python
from playwright.sync_api import Page

def test_example_test(page: Page):
  pass
  # "page" belongs to an isolated BrowserContext, created for this specific test.

def test_another_test(page: Page):
  pass
  # "page" in this second test is completely isolated from the first test.
```

### 使用夹具

你可以使用各种[夹具](https://pytest.cn/en/6.2.x/fixture.html#autouse-fixtures-fixtures-you-don-t-have-to-request)在测试前后执行代码并在它们之间共享对象。例如，具有 autouse 的 `function` 作用域夹具的表现类似于 beforeEach/afterEach。而具有 autouse 的 `module` 作用域夹具的表现类似于在所有测试之前和之后运行的 beforeAll/afterAll。

test_example.py

```python
import pytest

from playwright.sync_api import Page, expect

@pytest.fixture(scope="function", autouse=True)
def before_each_after_each(page: Page):
    print("before the test runs")
    # 在每次测试前转到起始url。
    page.goto("https://playwright.cn/")
    yield
    print("after the test runs")

def test_main_navigation(page: Page):
    # Assertions use the expect API.
    expect(page).to_have_url("https://playwright.cn/")

```
